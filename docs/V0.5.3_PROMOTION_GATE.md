# AXIOM V0.5.3 — Ω Promotion Gate

This stage turns the proof-oriented research fixtures into **unpublished promotion candidates** without changing the live 62-puzzle bank.

## Candidates

- `PC-C01` — Proof Compression, derived from `PC-P01`
- `NC-C01` — Necessary Clue, derived from `NC-P01`
- `CE-C01` — Counterexample Hunt, derived from `CE-P02`

Each candidate now has:

- four explicit semantic answer choices;
- an answer index checked against the finite verifier result;
- three spoiler-bounded hint stages: `structural → stronger → near_solution`;
- a separate post-answer explanation;
- deterministic generator/provenance metadata;
- explicit rendering and editorial readiness fields.

## Promotion rule

A candidate is **machine-ready** only when:

1. the source prototype verifier passes;
2. the semantic task has exactly one target answer;
3. the four displayed semantic options are distinct;
4. exactly one displayed option matches the verified semantic target;
5. all three hint stages exist and remain separate from the solution explanation;
6. the candidate is still unpublished.

A candidate is **promotion-ready** only when all machine checks pass **and**:

- rendering is implemented and verified;
- human QA is approved;
- difficulty review is approved.

Calibration is tracked separately and is not falsely treated as complete before player data exists.

## Current state

All three candidates are expected to pass the machine gate while remaining blocked from publication on rendering, human QA, and difficulty review. This is intentional: V0.5.3 creates the gate before changing the live bank.

The next promotion PR should implement visual rendering for these candidate kinds, browser-test all four options, perform human QA, then selectively promote only candidates that still satisfy the gate.

## V0.5.3 visual pipeline

- `src/candidate-graphics.js` draws original PNG-based cards for each candidate family; all cards must carry nonzero visible ink and remain distinct without relying only on text labels.
- `scripts/check-promotion-visual.mjs` uses Chromium to render 3 candidate sheets × 4 option cards at mobile and desktop sizes and save screenshots.
- The candidates are **not added to `PUZZLES`**: `published:false`, `render.ready:false` and editorial approval remains pending.
- `NC-C01` now uses **four clues** from `NC-P01`, matching exactly four selectable answer options. Its necessary clue remains the third clue.
- Actual browser rendering, human readability, and difficulty calibration are separate claims; a passing screenshot automation does not constitute human QA.
